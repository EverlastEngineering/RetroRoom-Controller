## Why bytes instead of `R""""( ... )""""` raw literal

The existing convention wraps HTML/JS in `R""""(` / `)""""` literals
that the C preprocessor doesn't tokenize as strings. I tried that
first with the YAML and the build failed:

    src/html/openapi.yaml:1:10: error: too many decimal points in number
        1 | openapi: 3.0.3
          |          ^~~~~
    src/html/openapi.yaml:7:39: error: stray '`' in program

The raw-literal trick only suppresses *string-literal* parsing; the
preprocessor still tokenizes `3.0.3` as a malformed float, backticks
as stray characters, and dashes as minus operators. Encoding each
byte as `0xNN` sidesteps all of that. The encoder script is one
Python file in `agent-script/`.

## Browser usage

Navigate to `http://192.168.1.100/openapi` in any browser on the
same network as the device. The page loads `openapi.yaml` from the
same origin, so "Try it out" works directly against the running
firmware. From `editor.swagger.io` or any other host, "Try it out"
will be blocked by CORS — there's a yellow banner on the page
explaining this.

## Workflow for future spec edits

